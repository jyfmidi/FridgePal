## 2026-08-01 preset food icon system

- The user selected code-native Vue/SVG curated icons as the production format. Prompt-generated imagery will serve as a reproducible style/shape reference, while final assets will be normalized to the existing 48×48 vector contract.
- The user initially selected a unified 40-icon first batch, but that fixed catalog is now superseded: it mixed fresh cooking ingredients with staples, condiments, and snacks and did not cover Chinese vegetables or fruit adequately.
- The user selected the `Bold Pantry` visual route: recognition-first semi-flat ingredient silhouettes on transparent canvas with no enclosing badge.
- Official 2022 Chinese dietary-guideline sources organize the pagoda into five broad groups: grains/tubers; vegetables and fruit; livestock/poultry/fish/eggs/milk; soybeans and nuts; cooking oil and salt.
- The official core recommendation calls for grains/tubers, vegetables and fruit, livestock/poultry/fish/eggs/milk, and beans in daily meals, with more than 12 foods per day and 25 per week. This supports a diverse preset icon library rather than a narrow produce-only set.
- The user clarified that the icon batch should model fresh cooking ingredients rather than reproduce the dietary pagoda. Under the product taxonomy, mixed beans are too generic, rice/pasta/bread are staples, olive oil is a condiment, and nuts are snacks; these should not consume priority slots in the fresh-food batch.
- The dietary guide remains useful as a coverage sanity check, but its nutritional food groups are not the correct information architecture for the preset Food Library.
- The official 2022 guidance provides category and example frameworks rather than a single fixed preset-food whitelist. Public guidance names whole-grain/mixed-bean examples such as millet, corn, mung beans, red beans, flower beans, buckwheat, and oats.
- The official dairy/soy section explicitly gives milk, yogurt, cheese, milk powder and tofu, dried tofu, and shredded tofu as interchangeable examples; it separately recommends nuts in moderation.
- The animal-food section prioritizes fish and calls for moderate fish, poultry, eggs, and lean meat; it recommends limiting processed meat, so the icon library should focus on raw fish/chicken/beef/pork/shrimp/eggs rather than sausage/bacon.
- The earlier guideline-aligned suggestion to add `mixed-beans` and `nuts` is withdrawn after the taxonomy clarification. The revised catalog should be demand-led within fresh-food categories, not forced to mirror every dietary-guideline group.

This is a cross-region assortment/demand signal, not a per-SKU ranking.

That basket is a stronger nationwide core proxy than a single city's app leaderboard: white radish, carrot, cauliflower, garlic scapes, oyster mushroom, shiitake, onion, lotus root, garlic, ginger, potato, celtuce, spinach, Chinese cabbage, scallion, chives, celery, lettuce, cabbage, bok choy, winter melon, green beans, cucumber, pumpkin, eggplant, sweet pepper, tomato, and zucchini.

Seasonal/local growth items can form a second tier rather than displacing everyday foods.

## AI provider integration

- MiniMax M3 exposes no server-side web search, so LLM-only "find meal ideas" would fabricate source URLs; retrieval requires a real search API (Tavily chosen) or the deterministic fixture.
- MiniMax Coding Plan keys authenticate on the OpenAI-compatible endpoint but are restricted to coding-plan models (M2 line) and the plan's terms limit use to coding tools; third-party app backends risk key suspension. A pay-as-you-go key is the correct choice for the app.
- DeepSeek's `https://api.deepseek.com/v1/chat/completions` is OpenAI-compatible, so the structuring adapter works for any OpenAI-compatible provider; only `factory.py` + env vars change on a swap.
- `Decimal.normalize()` can render quantities as `2E+2` inside generated search queries; a `format_quantity()` helper in `schemas.py` keeps query text human-readable.
- The safe-fetch boundary re-validates every redirect hop after DNS resolution and rejects loopback/private/link-local/CGNAT/metadata targets; residual DNS-rebinding TOCTOU is documented in the module docstring.
- Live adapters are selectable only through `RECIPE_PROVIDER_MODE=live` plus keys; missing keys raise at adapter build time, and fixture mode keeps the entire app usable offline.
- The structuring prompt isolates retrieved/source text inside an untrusted `<data>` block so page content can never act as instructions (prompt-injection separation).
- `ruff format --check` fails on pre-existing files, so the repo enforces only the configured `ruff check` rule set (E, F, I, UP, B, SIM); mypy and pytest remain the real gates.

## Docker Compose deployment

- The repository already has a working multi-stage `Dockerfile`, a two-service `compose.yaml`, and an environment template, but README still says application implementation has not started.
- Compose currently publishes `8080` on every interface, which conflicts with the canonical private/no-auth deployment boundary unless the host firewall restricts access.
- The repository has no `.dockerignore`; a server build can otherwise send `.git`, `frontend/node_modules`, `backend/.venv`, local databases, and caches into the build context.
- MySQL data already uses a named volume, and the application already runs Alembic before Uvicorn. A single app replica is therefore the supported deployment shape.
- Direct IP access does not require a domain or reverse proxy, but binding to `0.0.0.0` must be an explicit operator choice and port `8080` must be limited to trusted source IPs.
- Deployment documentation must warn that changing the Compose project name can make Docker attach a different database volume.
